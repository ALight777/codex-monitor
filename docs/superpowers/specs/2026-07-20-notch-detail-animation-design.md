# 刘海详情展开动画设计

## 目标

为刘海详情页增加与物理刘海连续的展开和收起动画，同时保持顶部 Codex 状态、中央刘海区域和右侧额度位置不变。

## 交互效果

### 展开

- 点击收起状态的刘海区域后，顶部窗口保持原位。
- 详情黑色外壳从刘海下沿向下延伸到当前内容所需高度，时长约 260 ms，使用 ease-out 节奏。
- 内容在外壳开始延伸约 60 ms 后淡入，并从向上偏移 6 pt 的位置回到正常位置。
- 外壳和内容共同呈现为一个从物理刘海延伸出来的整体。

### 收起

- 点击外部、按 `Esc`、再次点击刘海或打开设置时，都使用同一套收起路径。
- 内容首先在约 100 ms 内淡出并轻微上移。
- 外壳紧接着向刘海下沿回收，整体时长约 200 ms，使用 ease-in 节奏。
- 只在回收动画完成后将详情窗口移出屏幕层级，避免瞬间消失。

## 架构

### 窗口动画协调

`AppDelegate` 继续管理收起刘海窗口 `window` 和详情窗口 `detailWindow`。新增一个小型动画协调器，仅负责以下状态：

- 隐藏：详情窗口不参与显示。
- 展开中：详情窗口的顶边固定在刘海下方，下边向下移动。
- 已展开：窗口使用当前屏幕、安全区和内容计算得到的完整尺寸。
- 收起中：下边向上回收，顶边仍保持固定。

动画帧通过 AppKit `NSAnimationContext` 更新 `detailWindow` 的 frame。收起刘海窗口的 frame 不参与动画。

### 内容阶段

`OverlayState` 增加只读的详情内容显示阶段，`DetailPanelView` 使用该阶段控制内容容器的透明度和纵向偏移。黑色背景始终填满当前详情窗口，不随内容淡入淡出。

## 布局与屏幕适配

- 展开终点继续由 `ScreenNotchGeometry` 和 `IslandMetrics` 计算。
- 收起帧保留 `detailOverlap` 的重叠高度，确保动画起点在黑色刘海后方，不露出独立窗口边缘。
- 屏幕切换、分辨率变化、安全区变化和设置导致的高度变化，在已展开状态下直接对齐到新的最终 frame，不重播入场动画。

## 并发与快速操作

- 每次展开或收起会生成新的转换序号。
- 延迟内容动画和 AppKit 完成回调必须校验该序号，过期回调不得更改当前状态。
- 用户在动画期间反向操作时，从当前呈现 frame 继续到新目标，不先跳回动画起点。
- `restorePanelOrdering()` 只恢复层级，不重置 frame 或动画阶段。

## 辅助功能

当 macOS 开启“减弱动态效果”时，展开和收起直接设置最终 frame 与内容状态，不执行缩放、偏移或淡入淡出。

## 错误处理

- 无可用屏幕时不启动转换，保留当前显示状态。
- 动画期间的内容刷新只更新数据，不修改展开意图。
- 关闭完成后统一执行 `removeChildWindow` 和 `orderOut`，不保留可交互的透明窗口。

## 验证

- 单元测试覆盖展开、收起、连续反向操作和过期完成回调。
- 验证点击外部、`Esc`、再次点击刘海和打开设置的收起逻辑一致。
- 验证快速连续点击不会留下透明遮挡层、半展开窗口或错误的内容透明度。
- 验证展开和收起过程中顶部刘海 frame 保持不变。
- 验证正常动画模式和“减弱动态效果”模式。
- 运行回归测试与 Release 构建，安装后实机验证展开、收起和外部关闭。

## 非目标

- 不改动刘海收起状态的宽度、左右内容布局和物理刘海识别逻辑。
- 不为任务列表行、页签切换或额度数字增加独立动画。
- 不增加持续计时器、显示链接或其他空闲期资源消耗。
