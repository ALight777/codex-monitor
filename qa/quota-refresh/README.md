# 刘海额度跳变修复

验收日期：2026-09-08，Asia/Shanghai。

## 证据与复现

- 当前设置为“实时接口优先”。现场账号接口已用 22%，即剩余 78%；同一额度窗口的旧任务日志仍有已用 20%、剩余 80% 的记录。
- 原实现按接口取数时间和日志写入时间选择额度；日志时间较晚不代表其中的额度更准确。
- 接口刷新失败会把成功缓存覆盖为 failure，随后回退本地旧值。新增回归在原代码上复现了接口剩余 78% 后、读取失败和重试等待期间显示本地 80% 的问题。
- 原 shell 输入管道固定等待 2.2 秒后关闭。本次直接查询响应耗时约 2.271 秒，存在有效响应被提前关闭输入打断的窗口；没有采集到用户此前每次跳变对应的接口失败日志。

## 修复行为

- “实时接口优先”始终使用有效接口结果，日志写入时间不再覆盖接口值；接口返回的正常消耗、修正和额度重置均可生效，不做单调锁值。
- 首次成功读取之前保留本地兜底；之后的读取失败和 45 秒重试等待保留最后有效接口值。切换“仅本地记录”仍只使用本地数据。
- 空额度响应不覆盖成功缓存；额度重置次数等已有辅助信息合并逻辑保留。
- 直接通过 stdio 读取指定 JSON-RPC 响应，收到即返回，最长等待 4 秒；移除固定 sleep 和 shell 管道。无响应和忽略 SIGTERM 的子进程均有清理测试。

## 验证

- 原实现的新增回归失败，明确复现 78% 被日志/失败兜底替换为 80%。
- 修复后 7 项针对性测试通过，覆盖来源优先级、失败缓存、重试间隔、本地模式、正常消耗、重置、空响应、2.4 秒延迟响应和超时进程清理。
- `./scripts/run-regression-tests.sh`：72 项 Swift 测试通过，独立回归输出 `All regression tests passed`。
- 修复程序现场快照显示剩余 77%，说明能继续随实际消耗更新。
- 隔离源码的完整回归再次通过；arm64 与 amd64 Release、DMG 构建通过。本次为 0.1.16 的本机修复构建，未发布版本或推送仓库。
- 安装前保存原应用，安装后签名验证通过，安装与构建二进制 SHA-256 一致。实际应用已正常启动。
- 核验期间接口的重置时间更新，剩余额度变为 100%；修复版实际刘海显示 100%，与接口一致。安装后跨越接口缓存周期再次核对可访问性文本与截图，仍为 100%，未再观察到旧值覆盖。
