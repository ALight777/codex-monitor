# Radar 与空闲额度刷新修复

验收日期：2026-10-12（Asia/Shanghai）。本次为 0.1.17 的本机修复构建。

## 现场原因

- 本机 Codex CLI 已移动到 ChatGPT.app 内的 `Contents/Resources/codex-cli/CodexCLI.app/Contents/MacOS/codex`。旧实现只搜索 `Contents/Resources/codex` 与进程 PATH，桌面应用因此找不到实时额度查询程序，只能依赖有对话时写入的日志。
- 空闲快照缓存60秒，实时额度缓存30秒。旧实现直接返回整个快照缓存，额度查询也被一起跳过。
- [CodexRadar 官网](https://codexradar.com/) 已把原三维度归档，现行评分为64题、满分150分的 RadarBench。旧软件工程与视觉接口现场返回502，原缓存分别停留在10月5日和9日的检查结果。

## 修复

- 同时发现新旧 Codex / ChatGPT 应用内CLI、用户应用目录与PATH；每次需要查询时重新发现，支持应用升级后的路径变化。
- 空闲快照复用任务数据，同时独立执行按30秒缓存限流的额度查询；失败仍保留上次成功值。使用官方 [account/rateLimits/read](https://learn.chatgpt.com/docs/app-server) 接口，不发起模型对话。
- 雷达页只显示官网现行雷达Bench。按官网 binding 查询所有模型档位，最多4个并发，只请求公开 summary。校验题库摘要、版本、模型、档位、分数范围与覆盖范围，不自行重算评分。
- 每个成功档位更新，失败档位只复用同一题库、版本的旧成绩并标注“缓存”；新题库不混入旧分数。失败5分钟后重试，失败手动刷新可立即重试。
- 按用户后续要求移除已归档的三个旧维度入口及网络请求；启动时清除旧选择和首次迁移标记，旧缓存不再作为评分来源。官网仍保留“旧基准历史”，它不属于现行评分。
- 新评分的费用/耗时只计算已知样本均值，不完整的均值加星号说明；数据日期按官网UTC日桶，检查时间单列。

## 验证

- `./scripts/run-regression-tests.sh`：93项Swift测试通过，独立回归输出 `All regression tests passed`。
- 新增/补充覆盖：应用路径迁移、最小GUI PATH、无日志变化的空闲额度读取、额度失败保留与恢复、新评分解析/零分/待测、来源绑定校验、匿名请求、缓存迁移、部分失败与跨题库隔离。
- 实际 Swift 客户端查询34个档位，首轮26个成功、8个上游请求失败，25个已有评分、1个待测；数据日期为2026-10-12。部分失败被明确标注，不能将该轮称为全量成功。
- 使用 `PATH=/usr/bin:/bin` 运行修复版快速快照，成功读取实时剩余额度95%与3次重置额度；验证没有依赖当前终端注入的CLI路径。
